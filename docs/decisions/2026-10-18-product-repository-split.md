# Python 패키지와 macOS 앱의 저장소 분리 운영

- 결정일: 2026-10-18 KST
- 상태: 사용자 확정. 코드·CI·배포 구성의 분리는 후속 작업이다.
- 대체하는 결정: `heiccy`를 두 제품의 단일 개발·배포 원본으로 삼고
  `heic-converter-tui`를 과거 기록 보존용으로만 유지하는 방침.

## 결정

두 저장소를 제품별로 독립 운영한다. 각 제품의 개발·문서·이슈·PR·테스트·배포는
담당 저장소에서 관리하며, 같은 제품의 코드를 양쪽에서 계속 동기화하지 않는다.

| 저장소 | 담당 제품 | 배포 결과 |
| --- | --- | --- |
| `jaehunshin-git/heic-converter-tui` | Python CLI/TUI | PyPI의 `heic-converter-tui` |
| `jaehunshin-git/heiccy` | Swift macOS 앱 | `heiccy.app`·DMG·GitHub Releases |

Python 패키지명 `heic-converter-tui`와 실행 명령 `heic-converter`를 유지한다.
앱과 패키지의 버전·태그·릴리스 일정은 독립적으로 관리한다.
기존에 게시한 패키지·태그·릴리스를 이 결정에 맞춰 덮어쓰거나 재작성하지 않는다.

## 배경과 선택 이유

초기에는 비공개 개발 저장소에서 공개 `heiccy`로 소스를 내보냈고, 이후 두 제품을
`heiccy` 하나로 통합하는 방침을 정했다. 그 뒤 앱의 변환 엔진을 Swift와 macOS
Image I/O 기반으로 전환하여 앱 실행에 Python 패키지가 필요하지 않게 됐다.

2026-10-18 확인 시 두 저장소의 `src/heic_converter` 내 Python 소스 6개와
`pyproject.toml`은 동일하다. 반면 `heiccy`의 CI는 아직 Python 패키지 검사·배포
파일 빌드와 macOS 앱·DMG 빌드를 함께 수행한다.

단일 저장소에서도 CI·배포를 분리할 수 있지만, 현재 두 제품은 실행 엔진과 사용
방식이 다르다. 제품별 저장소를 두어 변경 범위·사용자 안내·이슈·배포 책임을
명확히 하고, TUI 변경으로 앱 빌드와 산출물 업로드가 발생하는 구조를 정리한다.

두 저장소의 설정을 각각 유지해야 하고 이미지·메타데이터 처리 정책의 변경을
양쪽에서 검토해야 하는 비용은 수용한다. 공통 요구사항은 필요한 제품별로 검증하며
양쪽 구현이나 변환 결과가 항상 같다고 가정하지 않는다.

## 유지할 경계

- `heic-converter-tui`는 Python 제품의 개발·배포 원본으로 유지한다.
  과거 기록 전용 저장소로 전환하거나 자동으로 보관 처리하지 않는다.
- `heiccy`에는 앱 빌드·검증·서명·패키징에 필요한 Python 도구를 남길 수 있다.
  Python 파일이라는 이유만으로 삭제하지 않으며 PyPI 제품 코드와 구분한다.
- 코드·CI 분리 후 `heiccy`에서 Python 제품의 wheel/sdist를 만들거나 PyPI에
  배포하지 않는다. Python 제품 변경으로 앱의 버전이나 릴리스를 갱신하지 않는다.
- 앱 코드·DMG 빌드는 `heiccy`가 담당한다. 기존 저장소의 macOS 앱 CI 중단은
  `heiccy`의 대체 빌드·검증 경로를 확인한 뒤 수행한다. Python에 필요한 macOS
  테스트는 별도로 유지한다.
- 과거 Git 이력·검증 문서·릴리스와 초기 `SOURCE.json`은 출처 기록으로 보존한다.
  `SOURCE.json`의 초기 기준 커밋·해시를 현재 코드에 맞춰 다시 작성하지 않는다.
- 사진·개인 파일·비밀정보·비공개 내부 기록을 공개 저장소로 복사하지 않는다.

## 공개 범위와 배포 안내

현재 `heic-converter-tui`는 비공개, `heiccy`는 공개다. 이번 결정으로 저장소의
공개 범위를 바꾸지 않는다. Python 제품의 공개 소스·문서·이슈 창구는 별도로
정하고, 외부 사용자가 실제로 접근할 수 있는지 확인한 뒤 안내와 메타데이터에
반영한다. 비공개 저장소 주소를 접근 가능한 공개 창구로 안내하지 않는다.

현재 Python 메타데이터의 `heiccy` 링크와 앱·패키지가 혼재한 README는 후속
정리 대상이다. PyPI 설명과 배포 메타데이터는 영어를 유지하고 패키지의 실제
기능·지원 환경에 맞춘다. 앱의 사용자 안내는 `heiccy`에서 관리한다.
